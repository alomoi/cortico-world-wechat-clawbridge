# 微信表情 ↔ 内部表情名 规格书

> 状态：**设计定稿，待实现**（2026-11-14）。实现要动 `config.js` / `emoji-map.js` / `segments.js` / `world.js` / `webui/client.js`，加测试后再发版。
> 前身：[emoji-map.md](emoji-map.md) 记录了 19 个表情词进 emoji 的原始设计，本文件只改「进微信」这一段。

## 目标

**只做微信渠道层的收发观感一致。**

| 谁 | 需要准确的地方 |
|---|---|
| 对方（微信） | 表情要画出来；没画出来也得是能读的字，不能是坏掉的标记 |
| 她（桌宠） | **字面就是语义**。收到什么字，就按什么字理解 |
| 插件 | 中间翻译，两头都不知道对方的名字怎么叫 |

**核心原则：她永远不需要知道微信那边叫什么。** 插件收到的、发出的，都已经是内部语义。所以提示词里**不写**任何「微信那边叫 xx」的对照——那只会让她多记一套名字，还可能写错。

---

## 一、三层规则

### 1. `【词】` —— 逻辑不变，只换对应

`【害羞】` 依旧表示「表情 + 换条消息」。改动只有一处：**最后贴上去的那个表情**，从 Unicode 换成微信表情名，并且**只在语义不变时换**。

> **1.8.0 起**：分条改教「一行一条」（换行），`【词】` 不再写进提示词，但解析保留——老写法、以及形象包自带 `【…】` 的桌宠照样兜得住。下面这段逻辑作为历史与兼容说明保留。

### 2. `[词]` —— 微信原生表情，透传

`[破涕为笑]`、`[旺柴]`、`[捂脸]` 是微信自己的表情代码，客户端会画成图。插件默认**原样透传**，一个字符都不碰。

### 3. `[自编词]` —— 转成全角圆括号

微信不认识的名字会原样显示成方括号加文字。与其让它「坏着显示」，不如转成微信里本来就很常见的叙述写法：

```
[歪头看鱼]  →  （歪头看鱼）
```

`（摸摸头）` 这种写法微信里到处都是，读起来是叙述，不是坏掉的表情，比「提示一个不存在的表情」代价小得多——**不丢内容、不需要她撤回、也不用纠结要不要重发**。

> 只转**方括号**的。正文里的「鱼在歪头看」不动。

## 三、别名表（用户维护，双向自动）

### 数据格式

```json
"emojiAliases": {
  "[破涕为笑]": "[笑哭了]"
}
```

**一列就够。** 键是「微信里的写法」，值是「插件内部的名字」。插件自动生成两份，各管一个方向：

| 方向 | 何时用 | 做什么 |
|---|---|---|
| 发出 | `clawbridge_send` 组装消息时 | 内部名 → 微信名（`[笑哭了]` → `[破涕为笑]`） |
| 收到 | 微信消息进入模型上下文前 | 微信名 → 内部名（`[破涕为笑]` → `[笑哭了]`） |

### 为什么必须是「两份分开查」而不是「一张表两头查」

一旦表被自动镜像，就必然出现同一个词既当源又当目标：

```
[破涕为笑] → [笑哭了]
[笑哭了]   → [破涕为笑]
```

实测一张表连着替换两遍的结果：

```
[破涕为笑] -> [破涕为笑]   ← 转了一圈回来，等于没换
[笑哭了]   -> [破涕为笑]   ← 方向也错了
```

**所以：每个方向只在自己的表里查一次，查完不再回头查。** 实现上就是一次 `replace` 遍历 + 长度降序排序（长词优先，避免 `[破涕为笑]` 被 `[破涕]` 截胡）。

### 默认预置

```json
"emojiAliases": { "[破涕为笑]": "[笑哭了]" }
```

理由：这是目前唯一确证的语义坑——她自己 11-13 的推理里就写着「He received 笑哭表情」，说明她理解的确实是笑哭。预置它等于让她**第一次看到就理解对**。用户随时可以在面板里删掉。

### 面板

在现有「绑定」「媒体」两个面板旁边加第三个「表情」：

```
微信表情 ↔ 内部名

[破涕为笑]  →  [笑哭了]     [删除]
[旺柴]      →  [旺柴]       [删除]

[ + 添加一行 ]

留空表示不转换。发出去会换成微信的名字，收进来会换成内部的名字；
她在提示词里只需要知道自己有哪些名字可用，不需要知道微信那边叫什么。
```

## 四、提示词怎么写（原则：能靠代码解决的就别教）

**教训（2026-11-09 → 11-13）**：1.7.1 在提示词里加了一句「回复正文里不要写 XML/HTML 标签（例如 `</text>`）」，
结果那句话**每次加载都又把 `</text>` 念了一遍**，反而成了泄漏源；删掉之后 `core.log` 里的
「剥掉模型漏出的标签」从 79 次降到 0。

**所以：插件能靠代码兜住的，一律不写进提示词。** 写进提示词的每句话都会变成新的诱导。

`ENV_PROMPT.md` 表情那一段收缩到两句：

> 表情写 `[名字]`，可用：{{clawbridge.emotes}}
> 微信那边的表情不止这些，看到新名字也可以学着用。

**第一句的清单是代码现算的**（2026-11-14 定）：

```js
// plugin/src/world.js:199
envPromptVars() {
  return { 'clawbridge.emotes': this.#emoteList() };  // 内置 19 + 别名表内部名
}
```

宿主 `build/cortico/src/core/prefix.ts:80` 每次渲染都会 `await mod.envPromptVars()`，
交给 `core/template.ts:25` 的 `renderTemplate` 替换 `{{名字}}`。所以清单永远和代码一致，
**不需要人维护一个字**——1.7.1 那张手写词表的失同步问题从根上没了。

不写「名字在面板里能看见」：面板是给你的，她看不到，「面板」二字只会变成一句空话。

**第二句是必要的**（用户 2026-11-14 定）：清单只列了插件认识的词，但她从微信收到的
`[旺柴]`、`[捂脸]`、`[抠鼻]` 这些也在 109 个之内、直接透传就到微信。不告诉她，
她就以为清单之外的名字是错的，会白白丢掉一大半可用表情。

**仍然不写**的东西，以及为什么：

| 本想写 | 为什么不写 | 改由谁兜 |
|---|---|---|
| 「微信那边叫 xx」的对照表 | 她只该有一套名字，两套就是两套记忆负担 | 插件 `emojiAliases` 自动翻译 |
| 「字面就是语义」 | 说了她也不会照着推理，写多了就是噪声 | 插件保证收发两头都是内部名 |
| 「别自己编名字」 | 与 `</text>` 同构：越提越容易写 | 插件把自编的转成 `（自编）` |
| 19 个词的清单（手写版） | 1.7.1 起就已和代码不同步，是旧隐患 | 改成代码现算的 `{{clawbridge.emotes}}` |

清单长度上限就是微信表情总数（109），实际是内置 19 + 别名表里新增的内部名，
一行放得下。

**踩过的坑（记一笔）**：
- `buildAliasTables()` 的两份表都是 `[key, value]`：`outbound` 的 key 是内部名，`inbound` 的 key 是微信名。
  取「内部名」要读 `inbound` 的 value，写反了清单里会冒出 `破涕为笑` 而不是 `笑哭了`。
- `buildAliasTables(DEFAULT_ALIASES)` 是恒等式（`[笑哭了]→[破涕为笑]→[笑哭了]`），
  用它当测试期望会让错误实现蒙混过关；正确写法是 `resolveAliases(undefined)`。
- markdown 链接 `[名字](url)` 会被转成 `（名字）(url)`——**已知取舍**，微信不渲染 markdown，
  链接照样能点，不为它加规则。

## 六、明确不做

- **不做表情包 (`[名]` → 发一张图) 的自动映射**（2026-11-14 定）：
  `images:["sticker:摸摸头无字版"]` + `text: "【开始】摸摸头"` 已经够自然，还比映射更灵活
  （她能自己决定这一条要不要配字、配什么字）。映射过去的话一张图必然单独成一条消息，
  埋进句子里就是刷屏，代价大于收益。
- **不做字符表情 (`(≧▽≦)` → `[名]`) 的映射**：那是纯文字，微信本来就原样显示，
  加一层翻译只会把本来通的东西翻错。她的字符风格应该从聊天里学，不由插件定义。
- **不打包微信的 109 张表情图**：版权归腾讯。
- **不维护 109 个微信表情的白名单**：微信会加，追不完；未知名字转圆括号就是兜底。
- **不让桌宠知道微信那边叫什么**：一套名字，一种理解。
- **不去改 `pet_say`**：那是气泡，和微信无关。
